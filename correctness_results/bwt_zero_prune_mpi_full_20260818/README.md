# BWT 空区间剪枝修复验证

## 修改原因

从核版 `bwt_seed_strategy1()` 曾在 FM-index 区间变空后直接跳到最小种子长度
阈值。这个提前返回忽略了阈值前可能出现的模糊碱基，因而不完全等价于主核
原始实现。

修复后仍然跳过空区间上的冗余 `bwt_extend()`，但会先扫描到阈值：遇到模糊
碱基时保持原来的重启位置，否则在原始循环达到长度阈值的位置返回。

## 完整数据验证

- 数据集：完整 `SRR2496709` PE
- 参考基因组：`GRCh38.d1.vd1.fa`
- 公共参数：`mem -v 4 -t 1 -I 170,80,500,1`
- MPI 输入：dynamic，`MPI_EXACT_READ_INDEX=1`
- 本轮未使用 `-1`

| 输出模式 | 排序后记录数 | 排序后字节数 | 排序后 MD5 |
| --- | ---: | ---: | --- |
| MPI single unordered | 25,396,635 | 8,119,600,200 | `b318cf90a083eafc9aa4c461bf023f90` |
| MPI split | 25,396,635 | 8,119,600,200 | `b318cf90a083eafc9aa4c461bf023f90` |

两个 MPI 输出与 x86 原版 BWA 的无 header SAM 在记录数、字节数和 MD5 上完全
一致。另行运行的 `cgs_cross + pool` 也得到相同结果。SE 已在此前完整数据验证
中通过，本轮按测试计划未重复运行。

目录只保存构建、运行、拼接和外部排序日志；远端的大型 SAM 文件未复制进版本库。
