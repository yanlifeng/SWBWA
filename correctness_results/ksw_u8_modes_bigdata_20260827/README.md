# CPE KSW u8 SIMD 模式大数据测试

## 测试目的

比较以下三种 CPE `ksw_u8` 后端的真实 Stage 2 性能与 SAM 输出一致性：

- `int32_16`：原始 16 lane、每个逻辑分数使用 32 位整数。
- `float16_16`：底层类型为 `float16v32`，仅启用低 16 lane，以保持原始 KSW stripe 与 Lazy-F 语义。
- `float16_32`：使用 `float16v32` 的全部 32 lane；这是实验性性能模式，会改变 stripe 宽度和 Lazy-F 收敛路径。

默认构建模式为严格且更快的 `int32_16`。三种模式通过
`make KSW_U8_MODE=...` 选择。

## 测试配置

- 执行模式：`cgs_cross + pool`
- 单节点、单进程、6 CG、每 CG 64 CPE
- PE，启用 `-1`
- 参数：`-v 4 -t 1 -I 170,80,500,1`
- 数据：`ERR1203383`、`small_SRR7963242`、`SRR2496709` 的大数据 FASTQ
- 每种模式和数据组合运行一次；Stage 2 与 part 3 是墙钟累计时间
- MD5 对完整无 header SAM 直接计算；三种模式的行数均相同

## 结果

| 模式 | 数据集 | Stage 2 (s) | CPE part 3 (s) | SAM 字节数 | MD5 状态 |
|---|---|---:|---:|---:|---|
| `int32_16` | ERR1203383 | 62.674 | 57.071 | 8,029,871,401 | PASS |
| `float16_16` | ERR1203383 | 71.563 | 67.621 | 8,029,871,401 | PASS |
| `float16_32` | ERR1203383 | 62.061 | 56.091 | 8,029,868,861 | MISMATCH |
| `int32_16` | small_SRR7963242 | 182.222 | 177.951 | 8,434,324,786 | PASS |
| `float16_16` | small_SRR7963242 | 189.064 | 185.821 | 8,434,324,786 | PASS |
| `float16_32` | small_SRR7963242 | 170.304 | 165.761 | 8,434,324,786 | PASS |
| `int32_16` | SRR2496709 | 60.550 | 55.713 | 8,119,600,200 | PASS |
| `float16_16` | SRR2496709 | 63.759 | 60.408 | 8,119,600,200 | PASS |
| `float16_32` | SRR2496709 | 59.365 | 54.242 | 8,119,579,664 | MISMATCH |

完整 MD5、行数和原始计时见 [summary.tsv](summary.tsv)，每个任务的完整日志位于对应模式子目录。

## 结论

1. `int32_16` 与 `float16_16` 在全部三组大数据上得到完全相同的 MD5、行数和字节数，说明 16-lane FP16 实现保持了当前严格输出语义。
2. 本轮单次大数据测试中，`int32_16` 的 Stage 2 在三组数据上均快于 `float16_16`，差距分别为 12.4%、3.6% 和 5.0%（以较慢的 FP16 时间为分母）。因此 FP16 指令本身的局部 cycle 优势没有转化为端到端收益。
3. `float16_32` 相比 `float16_16` 的 Stage 2 分别快 13.3%、9.9% 和 6.9%；三组累计时间下降 10.1%。但 ERR1203383 和 SRR2496709 的 MD5 不一致，且字节数分别少 2,540 和 20,536。它只能作为放宽逐字节一致性要求后的实验模式。
4. `small_SRR7963242` 上的偶然 PASS 不能证明 32-lane 语义等价；另外两组反例已经足以否定严格等价性。
5. 这些结果每个组合仅运行一次，适合判断明显趋势和正确性，不适合作为低个位数差异的最终统计结论。
